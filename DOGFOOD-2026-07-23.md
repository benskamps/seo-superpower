# Dogfood — 2026-07-23 — four live sites

Second dogfood pass (the first was [DOGFOOD-2026-05-12.md](DOGFOOD-2026-05-12.md),
one site). This one ran the no-OAuth path against four production sites and used
the failures to find structural bugs rather than site bugs.

**Sites:** brokenbranch.dev · thelongway.ai · vibecrafting.ai · visualinventory.ai

**Setup reality check:** the plugin author's own machine had **zero** SEO
credentials configured — no GSC OAuth, no PSI key. Three months after v0.3.0,
`/seo-setup` had never been completed here. That is itself the finding that
scoped this pass: the **No-MCP fallback is not an edge case, it is the default
experience**, for the author and for every first-time user. It got tested as
the primary path, because it is one.

## Structural findings

### F1 — Pass A gated the router on a number nobody computed  ◼ FIXED

`skills/seo-superpower/SKILL.md` step 4 listed ten checks and branched on the
tally: "if ≥8/10 pass, skip bootstrap, route to growth." Ten fuzzy conditions,
counted by a model, driving a branch. This is the exact failure mode
`scripts/detect-framework.js` was written to kill in `seo-bootstrap` Steps 1–2
— where a prose table claimed Astro and SvelteKit support for months while the
templates it pointed at did not exist.

**Fix:** `scripts/baseline-check.js` — deterministic, stdlib-only, 54 unit
tests, exit code carries the routing signal (`0` = healthy, `1` = incomplete,
`2` = unfetchable). Both skills now say *run the script, do not hand-tally*.

### F2 — The sitemap size limit was ~100× too strict  ◼ FIXED

`auditing-technical-seo/SKILL.md` checked "sitemap < 500 KiB (Google's hard
cap)" in two places, citing `[6][7]`. 500 KiB is the **robots.txt** parse cap.
A single sitemap's real limits are **50,000 URLs / 50 MB uncompressed**.

The tell: the skill's own `SOURCES.md` had both facts right and separate —
line 49 (robots.txt, 500 KiB) and line 51 (sitemap, 50k/50MB). And
`generating-programmatic-seo/SKILL.md:47` states the correct limit. **The
plugin contradicted itself between two skills**, and the wrong number sat in
the path that runs against every audited site. The research was never wrong;
the prose write-up conflated two numbers and then propagated the conflation
into an executable checklist.

**Fix:** corrected in both places, constants sourced in
`scripts/baseline-check.js`, and locked by a regression test asserting that a
600 KiB sitemap is perfectly legal and that the two constants are not the same
number.

### F3 — The AI-bot roster omitted the only bot that governs ChatGPT citation  ◼ FIXED

`OAI-SearchBot` appeared **nowhere in the repository** — not in
`templates/robots-ai-bots.txt`, not in any skill, not in any SOURCES claim.

Per [OpenAI's crawler documentation](https://developers.openai.com/api/docs/bots),
`OAI-SearchBot` "is used to surface websites in search results in ChatGPT's
search features," and sites that block it "will not be shown in ChatGPT search
answers." `GPTBot` — which the template *did* ship — is training-only and has
no bearing on citation.

The asymmetry is instructive: the repo researched Anthropic's three-bot split
carefully (`ClaudeBot` / `Claude-User` / `Claude-SearchBot`, documented in
SOURCES.md) and never applied the same lens to OpenAI, shipping two of its
three tokens and missing the search one.

This matters more than a missing string, because AI citation is the plugin's
headline promise. A user could paste the template, pass the AI-bot check, and
have said nothing about the single most load-bearing crawler.

**Live confirmation:** brokenbranch.dev's production `robots.txt` names eleven
AI crawlers under the comment *"canonical 2026 user-agent tokens"* — including
`Cohere-AI`, `Meta-ExternalAgent`, and the superseded `anthropic-ai` — and does
not name `OAI-SearchBot`. All three of the 10/10 sites have the same hole. They
are reachable only because their `User-agent: *` group happens to be
permissive: allowed by luck, not by policy.

**Fix:** template restructured by crawler **job** (retrieval / user / training)
rather than by vendor, because the job is what determines whether blocking costs
citations. `OAI-SearchBot` and `Perplexity-User` added. The skill now
distinguishes *named* from *effectively allowed*, and `baseline-check.js`
implements real robots.txt group resolution — most-specific agent, longest-path
rule, Allow-wins-ties — so it reports whether a crawler can actually reach the
site rather than whether someone typed its name.

### F4 — One key, two names, silent degradation  ◼ FIXED

`scripts/psi-quick.py` read `PSI_API_KEY` (17 references across the docs).
`.mcp.json` wired `PAGESPEED_API_KEY` (15 references). A user who followed
`MCP_SETUP.md` and set only the latter got a silent "CWV skipped" with nothing
pointing at why.

**Fix:** `load_api_key()` accepts either, canonical name first, in both env and
`.env` file lookup.

### F5 — The ≥8/10 threshold treats unequal things equally  ◧ FLAGGED, not silently changed

visualinventory.ai scored **8/10** and routed to *growth* with a "you're in good
shape" line. Its two misses were **no canonical tag** and **no AI-bot policy at
all** — a duplicate-content risk and the total absence of the thing this plugin
exists to fix. Meanwhile "exactly one `<h1>`" also counts one point.

A site can fail both of the two most expensive items on the board and still be
declared healthy. Changing the threshold is a product decision, not a bug fix,
so this pass did not change it. The router now carries an explicit warning to
read the miss list before celebrating, and to name a missing canonical or
AI-bot policy plainly rather than burying it in a cleanup bullet.

## Domain claims re-verified (July 2026)

Enrichment pass against primary sources. Not everything drifted — two claims
came back clean, which is worth recording so they don't get "fixed" later.

| Claim | Verdict | Source |
|---|---|---|
| Sitemap < 500 KiB | **Unsupported** — that is the robots.txt cap | Google Search Central (A) |
| Sitemap limits: 50,000 URLs / 50 MB | **Supported** | Google Search Central (A) |
| robots.txt parse cap: 500 KiB | **Supported** | Google robots.txt spec (A) |
| CWV p75: LCP<2.5s, INP<200ms, CLS<0.1 | **Supported**, all three Stable | web.dev/articles/vitals (A) |
| `OAI-SearchBot` governs ChatGPT citation | **Supported** — and was missing | OpenAI crawler docs (A) |
| `llms.txt` ~10% adoption, effect unproven | **Supported** — and stronger than stated | multiple (B/C) |

On `llms.txt`: the skill's position ("adoption ~10%, no measurable AI-citation
effect, flag as suggestion only") is **correct and worth defending**. June 2026
adoption measured 8.7% of the top 1,000; Ahrefs found 97% of ~38,000 domains
with a valid `llms.txt` received zero requests for the file in May 2026; Google
has confirmed it does not use the file. Several competing plugins in the
directory sell `llms.txt` generation as a headline feature. This one declined
to, on evidence, before the evidence was this strong.

## Per-site actions (owner repos, not this one)

Not applied by this pass — these live in other repositories.

**All three 10/10 sites** — add `OAI-SearchBot` to `robots.txt`. Currently
allowed only by a permissive wildcard. One stanza, from the updated
`templates/robots-ai-bots.txt`:

```
User-Agent: OAI-SearchBot
Allow: /
```

**visualinventory.ai** — two fixes:
1. Add `<link rel="canonical">`. The site redirects apex → `www`, so the
   canonical should be absolute and `www`-consistent. Duplicate-content risk
   until then.
2. Add the AI-bot stanza. `robots.txt` currently has only a `User-agent: *`
   group with `Disallow: /api/ /dashboard/ /admin/ /auth/callback` — sensible,
   but zero AI policy. For a product whose whole pitch is AI-assisted
   inventory, being silent on AI crawlers is the wrong default.

## What this pass did not test

Honest gaps, so the next pass knows where to start:

- **CWV / PageSpeed** — no `PSI_API_KEY` available. Zero field data collected.
- **GSC-dependent skills** — `finding-underserved-keywords`,
  `refreshing-stale-content`, and the decay hooks need OAuth. Untested here,
  and untested on this machine ever.
- **`geo-check` / `geo-diff` MCP** — needs paid LLM API keys. The servers import
  clean in CI and make real HTTP calls, but no live citation run happened.
- **Inner pages** — Pass A covers the homepage. Only sitemap and robots are
  site-wide.

The unifying gap: everything gated behind `/seo-setup` remains unexercised.
The single highest-value next step for this plugin is not another feature —
it is completing `/seo-setup` once, on one real property, and finding out what
breaks.
